# 早押しイントロクイズ

Apple Music の楽曲を使った、リアルタイム同期型の早押しクイズアプリです。
1 台の PC でゲームサーバーを起動し、ホストはスマホの**ホストコンソール**で進行、観客は**ゲームボード**を大画面で観戦、プレイヤーはスマホや物理ボタンを**早押しボタン**として使います。すべての画面・ボタンはリアルタイムに同期します。

ゲームは、短い再生から曲名を当てる**イントロモード**と、難読化されたアルバムジャケットからアルバム名を当てる**ジャケットモード**を選べます。
ジャケットモードは選択曲から重複を除いたアルバム一覧を作り、同じアルバムの曲が複数あっても出題は 1 回にまとめます。

## 構成

| 画面 / API | パス | 役割 |
| --- | --- | --- |
| ホーム | `GET /` | 各画面へのリンク集 |
| ホストコンソール | `GET /console` | Apple Music ログイン・曲選択・ゲーム進行（ホスト操作） |
| ゲームボード | `GET /gameboard` | 大画面向けの観戦表示 |
| 早押しボタン | `GET /action` | スマホを早押しボタンとして使うプレイヤー向けページ |
| アクション信号 | `POST /api/act/:actorId` | プレイヤー / 物理ボタンからの早押し・参加トグル |

## 必要なもの

- [Bun](https://bun.sh/)
- Apple Developer Program のメンバーシップ（MusicKit 用の developer token を発行するため）
  - Team ID
  - MusicKit 対応の Key ID と、その秘密鍵 (`.p8`)
- Apple Music のサブスクリプション（ホストがライブラリのプレイリストを再生するため）
- ホストコンソールはサーバーを起動した PC の `http://localhost:<PORT>/console` で開くこと（Apple Music のログインは secure context が必要で、HTTP 配信では `localhost` のみ該当）

## セットアップ

### 1. 依存をインストール

```bash
bun install
```

### 2. 環境変数を設定

`.env.example` をコピーして `.env` を作成し、各値を記入します（必要な変数とその説明は `.env.example` を参照してください）。

```bash
cp .env.example .env
```

`APPLE_*` が未設定の場合、Apple Music のログイン・再生はできません。

### 3. 起動

```bash
bun dev
```

`bun --hot` で Bun サーバーをホットリロード付きで起動します。`0.0.0.0` で待ち受けるため LAN 内の端末からアクセスできます。起動時のログには `localhost` のホストコンソールとゲームボードの URL を表示します。LAN 内の端末向けの URL はホストコンソールの「2. 準備」カードからコピーします。HTTP のみで配信します。

## 遊び方

1. **ホストがログイン** — サーバーを起動した PC で `http://localhost:<PORT>/console` を開き「ログイン」。ログインするとライブラリのプレイリスト一覧が自動取得されます。
2. **曲を選ぶ** — プレイリストを複数選択すると、その曲がまとめて出題候補になります。
   「再読み込み」横のボタンでリスト表示とツリー表示を切り替えられます。ツリー表示ではフォルダを選ぶと、サブフォルダも含めた中のプレイリストをまとめて選択 / 解除します。
3. **プレイヤー参加** — 各プレイヤーは `/action` を開く（または物理ボタンを用意する）。準備フェーズ中にボタンを押すと参加 / 退出がトグルします。参加者はゲームボードに表示されます。
4. **ゲーム開始** — ホストが「イントロで開始」または「ジャケットで開始」。曲順はシャッフルされ、全員のスコアが 0 にリセットされます。
5. **ヒント提示** — イントロモードでは再生秒数（0.1〜30 秒）を指定して「再生」。ジャケットモードでは隠し方、白黒、ヒントレベル（1〜100%）を調整します。
   イントロは指定秒数または曲末で停止し、読み込み待ちは再生秒数に含めません。再生中に秒数を変更した場合は次回から反映します。
6. **早押し** — イントロモードでは再生中、または一度でも再生した後に受付。ジャケットモードではジャケット表示中に受付。参加プレイヤーが最初にボタンを押すと解答権を獲得します。
7. **正誤判定** — ホストが「正解」/「不正解」を判定。正解なら +1 点で正解発表へ、不正解なら再び早押し受付に戻ります。ホストコンソールの「3. 進行」カードにある「回答」欄にプレイヤーの回答を入力して候補（最大 5 件、曖昧一致）から選ぶと、出題中の曲 / アルバムと照合して自動で判定します。
8. **正解発表 → 次へ** — イントロモードの正解発表中は曲をフル再生（ループ）。ジャケットモードでは出題中にアルバムを無音で事前準備し、正解発表で元のジャケットとアルバム名を表示して、そのアルバム全体を曲順どおりにリピート再生します。事前準備が完了していれば、正解発表時のアルバム取得・読み込み待ちを省けます。次のラウンドや結果発表で停止します。ホストは「次のラウンドへ」で次の曲、「結果発表へ」でスコアボードを表示します。
9. **次のゲーム / リセット** — 「次のゲームへ」で参加者をクリアして準備フェーズへ。「リセット」で初期状態まで戻します。

ホスト画面を閉じて開き直したり再読み込みした場合、イントロは停止して待機へ戻ります。解答者・得点・出題は復元され、判定演出・正解発表・結果表示からも進行を続けられます。再生不能と判明した曲は、その時点で選曲・出題から除外します。

### ジャケットモード

ジャケットモードでは、ホストコンソールの「3. 進行」に次の操作が表示されます。

- **隠し方** — モザイク、穴あき、タイルシャッフル、スポットライト、ズーム＆回転、ふちから表示
- **白黒** — どの隠し方にも適用できる ON/OFF 設定（デフォルトは ON）
- **ヒントレベル** — 1〜100%。数値が大きいほど元のジャケットに近づきます

## 物理ボタンの接続

物理ボタンは `POST /api/act/:actorId` を叩くことでスマホの早押しボタンと同じ働きをします。`:actorId` はボタンごとに固定の任意の ID です。レスポンスボディは空で、反応の有無は HTTP ステータスコードで示します。

| ステータス | 意味 |
| --- | --- |
| `200 OK` | 反応あり（参加トグル成功、または解答権の獲得） |
| `204 No Content` | 正常だが反応なし（すでに他の人が解答権を取得済み 等） |
| `400 Bad Request` | `actorId` が空 |
| `409 Conflict` | 今は受け付けられない状態（未参加での早押し、受付時間外 等） |
| `429 Too Many Requests` | クールダウン中（同一プレイヤーの受理済み action は最短 250ms 間隔） |

## スクリプト

| コマンド | 内容 |
| --- | --- |
| `bun dev` | 開発サーバー |
| `bun start` | 本番起動 |
| `bun run typecheck` | 型チェック |
| `bun run lint` | ESLint |
| `bun run test` | feature / step defs 回帰テスト |

### テスト

テスト専用のサーバーを起動し、その URL を `TEST_BACKEND_URL` に指定して `bun run test` を実行します。普段のゲーム用サーバーは使わないでください。

## 技術スタック

- ランタイム / サーバー: **Bun** (`Bun.serve`)
- WebSocket: **Socket.IO** + **@socket.io/bun-engine**
- フロントエンド: **React 19**（Bun サーバーが配信する SPA）
- 音源: **Apple MusicKit JS v3**
- トークン署名: **jose**（ES256 JWT）
